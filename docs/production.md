# Production operation

Use HTTPS for phone enrollment and PAM traffic. Keep the backend bound to loopback or a private container network and expose it only through a TLS reverse proxy. Do not publish the database or Redis ports.
Back up the SQL database and secret configuration together before any upgrade. Startup performs additive schema migrations; rehearse upgrades against a copy and never overwrite live state with an older database.
Use one server process for SQLite. PostgreSQL is the supported shared database for multiple processes; Redis supplies low-latency fanout, while SQL reconciliation repairs missed stream events.
`/healthz` measures application liveness only, never touching the database. `/readyz` is readiness: 200 while the database answers within 3 seconds and, on PostgreSQL, accepts writes (`transaction_read_only` is off; SQLite runs `SELECT 1`), otherwise 503 `{"database": "unavailable"}`. A login that reaches a read-only PostgreSQL server (a standby or demoted leader during failover) gets 503 `database_unavailable`, like a lost connection. It runs one check at a time and reuses the result for a second, so probes never load the database; neither path is rate limited. Use `/healthz` for restarts and `/readyz` for routing and alerting, and keep `/readyz` on the private network. Monitor both and alert on failed delivery, rate limits and database errors. SQL statement and lock limits default to 15 and 5 seconds.
The built-in limiter is bounded in-memory per process. Configure reverse-proxy rate and connection limits as well, especially for multiple instances and WebSockets. Trust forwarded client IP headers only from your known proxy.
Keep enrollment QR codes, integration HMAC credentials, API keys, phone signing keys and database backups private. Revoke lost devices and lock users promptly. SQL bind parameters are hidden in errors, but request metadata remains sensitive.
Default fail mode is closed. Trusted sessions are disabled. Avoid fail-open, offline factors and trusted sessions on SSH integrations; `online_only` provisioning enforces this. On a PAM host, `PUSHGATE_FAIL_CLOSED_USERS` (comma or space separated) lists accounts that never pass on an outage: for them a cached fail-open mode and offline codes are ignored, so only a live approval logs in; use it for service and automation accounts. Keep a separately tested local recovery console before changing PAM.
Use your own signing identity for Android releases. A release signed by a different key is a separate application trust decision.
