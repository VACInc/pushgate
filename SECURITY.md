# Security policy

Version 1.0.1 is the supported source release. Review the threat model before using it to protect SSH.
Report vulnerabilities privately through the repository host's private vulnerability reporting feature. Do not include credentials, enrollment codes, private keys, production logs or personal data in public reports.
If private reporting is unavailable, ask the maintainer for a private contact channel without posting exploit details. The publisher must enable private reporting before release.
Provide affected version, minimal synthetic reproduction, impact and expected behavior. No response-time guarantee is offered.
A valid approval is single-use and expires. Locking either principal or approver, or revoking the approving device, invalidates an outstanding grant at consumption time. Fail-closed PAM configuration is strongly recommended.
